# 缺陷 RCA（Personal Workbench）

完整模板见 `docs/playbooks/incident-rca.md`。目标不是“修好这一条”，而是“让同一不变量不再被违反”。

## 步骤

1. **复现**：最小命令/最小数据；记录环境、数据根、版本、退出码。
2. **分类**：契约漂移 / 状态事务 / 安全边界 / 静默回退 / 测试 CI / 文档快照。
3. **5 Whys**：写到“为什么流程允许它发生”，不要停在“手误”。
4. **查不变量**：`docs/INVARIANTS.md` 是否已有？有就指向它，不新建编号；没有就加一行。
5. **先写失败测试**：TDD；测试必须能在修复前红、修复后绿。
6. **修复**：最小改动；同步前端/文档/迁移说明。
7. **验证**：聚焦 + 相关全量 + 契约检查；记录命令/退出码/通过数。
8. **沉淀**：如果是新类型，更新 AGENTS 规则/检查器/Skill；如果是重复类型，补不变量测试。

## 必须回答

- 这个问题的“不变量”是什么？一句话。
- 哪个测试会在它再次发生时红？
- 哪个边界（前端/后端/文档/DB/外部引擎）没有单一源？
- 是否可以用 4xx/409/unknown 代替静默回退？
- 是否依赖真实路径/端口/外部任务？如果是，改成什么夹具？

## 禁止

- 不为了过测试而 skip/删断言/降阈值。
- 不在没有复现的情况下猜根因。
- 不把“设计取舍”当 bug 修（先看 `docs/ARCHITECTURE.md` §7）。
- 不新建一个与旧编号重复的台账条目；先查 `docs/INVARIANTS.md`。
