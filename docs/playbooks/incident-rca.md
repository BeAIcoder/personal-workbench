# 缺陷 RCA Playbook

> 适用：修 bug、回归、返工、回滚；或把一次事故沉淀成规则/测试。
> 相关 Skill：`.agents/skills/pw-incident-rca/SKILL.md`。

## 1. 复现（先于任何修复）

记录：

- 版本/提交、分支、工作树是否干净。
- 数据根四域：`WORKBENCH_DATA_DIR`、`DATABASE_URL`、`FINANCE_DATA_DIR`、`DEBUG_DATA_DIR`。
- 最小命令/最小数据/退出码/日志路径。
- 是否依赖真实路径/端口/外部任务（如果是，先改成夹具）。

## 2. 分类（六选一）

| 类型 | 典型信号 | 先查 |
|---|---|---|
| 契约漂移 | 前后端字段/超时/菜单/文档对不上 | 单一源 + 契约测试 |
| 状态/事务 | 卡在 running/uploaded、重复期间、删级联 | 状态机/唯一约束/IntegrityError |
| 安全边界 | 账号/Key/PII/根目录/模式 fail-open | serializer/guard/枚举 |
| 静默回退 | 非法期间→当前、GBK→关键字失效、未知→默认 | 4xx/unknown |
| 测试/CI | 真实路径/端口、无 DOM、无建表、无超时 | tmp_path/jsdom/pytest-timeout |
| 文档快照 | 旧名/旧计数/旧截图/ADR 过期 | as-of/归档/ADR 状态 |

## 3. 5 Whys

写到“流程为什么允许它发生”：

- 为什么出现？→ 代码/配置/数据。
- 为什么没拦住？→ 测试/检查/评审。
- 为什么测试没覆盖？→ 环境/夹具/断言方式。
- 为什么流程允许？→ 没有单一源/没有不变量/没有快速反馈。
- 为什么现在才发现？→ 审计/CI/用户路径。

## 4. 先写失败测试

- TDD：修复前红、修复后绿。
- 测试要覆盖“不变量”，不只是这次的具体输入。
- 如果是不变量复发，先查 `docs/INVARIANTS.md`，指向已有条目；不要新建编号。

## 5. 修复与验证

- 最小改动；同步前端/文档/迁移说明。
- 金额 `money()`；期间/枚举严格；`IntegrityError`→409；状态失败回收。
- 跑聚焦 + 相关全量 + 契约检查；记录命令/退出码/通过数。
- 不在测试里 skip/删断言/降阈值。

## 6. 沉淀

- 新类型：更新 `AGENTS.md` 规则 / 检查器 / Skill。
- 重复类型：补 `docs/INVARIANTS.md` + 永久测试。
- 历史报告：只加状态说明，不改写；在 `progress.md` 追加本轮记录。
- 如果发现是“设计取舍”，在 `docs/ARCHITECTURE.md` §7 写清，不要当 bug 修。

## 7. 输出模板

```markdown
## 现象
## 复现（命令/数据/环境）
## 根因（5 Whys）
## 不变量（INV-xxx）
## 修复
## 验证（命令/退出码/通过数）
## 防复发（测试/规则/检查器）
## 未关闭/外部阻断
```
