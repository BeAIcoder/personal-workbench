## 三、关键决策记录（ADR 摘要）

| # | 决策 | 理由 |
|---|------|------|
| D1 | 以 personal-workbench 为唯一宿主，不做新应用、不做微服务 | 评审否决重写式平台化；工作台已成熟且在维护 |
| D2 | 先补"目录扫描式 Module Registry"（后端 manifest+动态 include_router / 前端 glob+菜单数据驱动），再接业务模块 | 业务层加实体改 8 处是当前最大扩展瓶颈；模块即插件、故障域隔离 |
| D3 | 四级接入（L0 直挂 / L1 任务薄壳 / L2 产物聚合 / L3 登记），按引擎性质分流 | 重浏览器自动化与 COM 依赖不适合进 Web 进程；纯函数引擎零成本复用 |
| D4 | 不引入 Alembic，沿用 PRAGMA 轻量补列；模块表强制 `mod_<name>_*` 前缀 | 保持项目轻量惯例；前缀防模块间表名冲突 |
| D5 | 统一 `/api/finance/` 命名空间 + `data/finance/<module>/inbox|outbox` 目录约定 | 路径治理一次到位，上传防穿越复用现有机制 |
| D6 | 模块能力经 manifest 声明自动注册进 Agent 工具白名单（仅查询/创建类） | 让 AI 助手能跨模块问答（"上月费用分类汇总"）；遵守"删除不开放给 Agent"既有决策 |
| D7 | 新增依赖红线：仅 MIT/Apache-2.0/BSD | 用户指定 MIT 优先；Apache-2.0/BSD 与 MIT 兼容故放行并标注 |
| D8 | 现金流模块整体进 `.gitignore`，提交前跑 FSSC 同款脱敏自检 | V1 永不推远端的既有声明延伸到工作台 |
